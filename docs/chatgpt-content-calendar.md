## 一、先选一个有材料的主题

练习主题为“用ChatGPT比较两份活动方案”。已有两份虚构原文、差异表和检查方法，截图仍需实际操作。先把这些材料整理好，再安排发布时间。

```text
请为这个主题制定一周内容计划。
平台：GitHub、网站博客、知乎、公众号、视频号、X。
目标：帮助读者学会核对版本差异。
已有：完整原始材料和参考答案；未有：实测截图。
不编造搜索量、热度、阅读量或转化率。
```

给出已有材料和缺口，有助于把计划变成可执行任务。[官方提示指南](https://learn.chatgpt.com/docs/prompting)

<a id="section-02"></a>

## 二、让每个平台承担一个具体作用

| 平台 | 本例内容形式 | 需要保留的价值 |
|---|---|---|
| GitHub | 完整教程与练习材料 | 可复现的步骤和原文 |
| 网站博客 | 完整解释与常见疑问 | 可独立读懂的解决方法 |
| 知乎 | 围绕具体问题的回答 | 先解决提问，再提供延伸阅读 |
| 公众号 | 一次完整实践故事 | 输入、输出与人工核对过程 |
| 视频号 | 演示一个关键误差 | 观众能看清操作和修改 |
| X | 简短要点与局部示例 | 一条明确结论及来源入口 |

这些是表达建议，不是对平台推荐算法的保证。是否适合英文内容，要看你实际想服务的读者，不必为覆盖平台而强行翻译所有文章。

<a id="section-03"></a>

## 三、按依赖关系排期

先实测并补截图，再审定主教程；主教程事实稳定后再写回答、图文和视频。短内容引用的最终链接，要在对应文章真的上线后检查。

可以按“第1次工作整理材料、第2次工作实测、第3次工作审稿、第4次工作改编”安排，而不是硬定每天必须发几篇。实际耗时由你记录，不把编辑估计当成已验证效率。

<a id="section-04"></a>

## 四、把计划细化成每项交付物

```text
请为每个平台列：核心问题、标题候选、需要材料、完成标准和依赖项。
标题不得承诺不存在的功能或效果。
视频先给镜头表，不假设已经录制。
缺少的实际截图单独列出，不用生成图片冒充产品界面。
```

例如视频只演示“6处变更和2处不变如何核对”，而完整原文放在主教程里。短内容也应提供足够说明，让读者理解为什么这样检查。

<a id="section-05"></a>

## 五、发布后根据真实反馈调整

记录读者问了什么、哪些步骤看不懂，以及可观察到的相关访问和咨询。若大家反复问同一个操作，就先完善主教程，再更新各平台摘要。

需要把事实材料改成文章与脚本，可看[公众号和视频号案例](chatgpt-content-workflow.md)；想先规划搜索问题与文章结构，可看[SEO文章需求单](chatgpt-seo-article-brief.md)。
