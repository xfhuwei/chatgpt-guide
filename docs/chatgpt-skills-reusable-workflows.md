## 一、先区别技能、项目和插件

项目用于组织一项工作的相关资料；技能保存可反复执行的方法；插件可以把技能与外部工具打包。安装某个插件，不自动等于取得外部账号授权。[技能与插件说明](https://learn.chatgpt.com/docs/skills-and-plugins)

如果只是临时要求一篇短文，用普通提示词即可。先手动跑通一个任务，再把稳定做法整理成技能，能够避免把未验证的要求固化。

<a id="section-02"></a>

## 二、设计一个小而明确的技能

下面是原创“文章审核进度简报”规格：

```text
输入：文章名称、当前状态、缺少材料、下一步安排。
输出：本周已完成、待处理、需要确认，三部分。
固定规则：交初稿不等于发布；没有截止时间就不补日期。
检查：篇数一致；每项待处理能追溯到原始记录。
适用：整理文章进度，不负责发布文章或发送消息。
```

一次只解决这一件事。若还要做图片、查账单、发邮件，先另列需求，不把所有工具塞进第一个技能。

<a id="section-03"></a>

## 三、通过当前支持的创建入口生成草稿

官方说明在ChatGPT中可从 `@skill-creator` 开始，在Codex中使用 `$skill-creator`。说明任务、输入、输出和限制，并给出一个好例子。可用范围与安装方式按实际账号或工作区判断。[技能创建流程](https://learn.chatgpt.com/docs/skills-and-plugins)

```text
请把上面的文章进度整理方法做成一个技能草稿。
先展示名称、适用条件、步骤和验收方法。
不要添加发布、发送或读取其他账号的操作。
```

<a id="section-04"></a>

## 四、用正常材料和缺项材料各试一次

第一组原创材料：文章A已发布，文章B初稿完成但缺截图，文章C尚未开始；B和C的期限都未确定。结果应为1篇已发布、1篇待审核配图、1篇待开始。

第二组故意缺少文章B的状态。合格表现是指出缺项，而不是按经验填成“已完成”。还可以补一条相互冲突的记录，看它能否列出冲突让你确认。

记录失败发生在哪一步，修正具体要求，再重试相同材料。技能成功被选中，不代表输出已经符合标准。

## 五、启用后怎样维护

保留版本说明、两组练习和正确标准。业务流程变了，就改具体步骤再验证。使用外部资料时，另行检查连接和权限；技能说明里不应保存密码、验证码或个人密钥。

需要工具连接时看[插件教程](chatgpt-plugins-connected-apps.md)；只有固定表达偏好时，用[自定义指令与项目](chatgpt-projects-memory-instructions.md)可能更直接。

需要协助配置自己的工具、工作流或知识库时，可了解[小小AI安装与定制服务](https://xiaoxiao-ai.com/?utm_source=github&utm_medium=referral&utm_campaign=chatgpt_guide&utm_content=a49_implementation)。这是维护者提供的独立第三方服务；先说明设备、输入、目标与验收要求，再确认范围和费用。
