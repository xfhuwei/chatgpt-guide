# 用 ChatGPT 写会议纪要和周报：原始记录、提示词与核对示例

资料核对：2026-11-03。本文为原创虚构办公练习，不含真实客户数据或实际提效统计。

> **先看结论：** ChatGPT适合把散乱记录整理成结构清楚的纪要，但整理不等于替你确定事实。最常见的错误，是把“建议下周做”写成“已决定下周完成”，或给未分配的任务补上一个负责人。

本篇从完整原始记录开始，先做会议纪要，再在收到真实进展后生成周报。

## 一、把这份原始记录发给ChatGPT

```text
会议：知识库内容讨论，11月3日，14:00—14:30。
参会：小林、小周、小陈。
小林：注册教程初稿已经完成，手机截图还没补。
小周：可以考虑做一份常见问题合集，但今天不决定是否做。
决定：本周先完善注册教程，不同时启动新的长篇专题。
任务：小陈在11月5日18:00前补手机截图。
任务：小林收到截图后检查文字与按钮名称，11月6日12:00前交修订稿。
问题：支付失败案例缺少可以公开使用的真实截图。
下次检查时间：11月6日16:00。
发布负责人：尚未确定。
```

这些内容用于练习，不对应真实工作安排。可以直接粘贴到对话里；实际工作中的资料应先确认可分享范围。

<a id="section-02"></a>

## 二、第一轮生成纪要

```text
请仅根据以上记录生成会议纪要。
输出：1.会议信息；2.已确认决定；3.行动项表格；4.待确认问题。
行动项表格包含：任务、负责人、截止时间、依赖条件。
明确区分建议与决定，不把尚未决定的常见问题合集写入已安排工作。
原文没有的负责人或时间写“待确认”。
```

可以对照下面这部分参考结果检查：

| 任务 | 负责人 | 截止时间 | 依赖条件 |
|---|---|---|---|
| 补手机截图 | 小陈 | 11月5日18:00 | 无已知前置条件 |
| 检查文字、按钮名称并交修订稿 | 小林 | 11月6日12:00 | 先收到截图 |

“常见问题合集”应保留为未决定的建议；“发布负责人未确定”和“缺少可公开截图”应进入待确认问题。上述表格为人工编写的参考答案，实际模型输出需要逐项对照。

<a id="section-03"></a>

## 三、先核对，再发送给参会人

用“谁、做什么、何时、前提是什么”逐行检查。尤其注意：小林的截止时间不能写到小陈名下；“收到截图后”不能被省略；检查会时间不能被当成发布时刻。

还可以继续追问：

```text
把纪要中的每个决定和行动项对应到原始记录中的一句话。
凡是找不到依据的项目，标为“无原文依据”，不要补写来源。
```

这个核对法采用了[官方提示指南](https://learn.chatgpt.com/docs/prompting)中提供背景、限定输出与后续修正的思路，具体材料和表格是本知识库的原创练习。

<a id="section-04"></a>

## 四、生成周报前，要补充实际进展

会议安排不是完成记录。假设到了周五，你拿到了以下虚构更新：

```text
截至11月6日15:00：
小陈已在11月5日提交3张手机截图。
小林已完成文字检查，发现其中1张按钮名称与网页版不同，正在补注平台说明。
修订稿尚未最终确认。
常见问题合集仍未立项。
支付失败截图仍缺。
```

发送下一条要求：

```text
结合会议纪要和这份最新进展，写一份不超过300字的周报。
结构：已完成、进行中、阻碍、下一步。
以最新进展判断状态；原来计划完成但尚未完成的内容，不能写成已完成。
下一步可提出建议，但请明确写成建议，不代替负责人作承诺。
```

<a id="section-05"></a>

## 五、周报的合格结果应该有什么

已完成应包含提交3张截图和已进行的文字检查；进行中应包含平台说明和未最终确认的修订稿；阻碍是可公开支付失败截图仍缺。

若结果写成“本周已完成注册教程发布”，就超出了原始材料。若把“常见问题合集”写成下周必须上线，也属于把未决定事项变成承诺。

下次处理自己的资料时，保留这两个输入：原始会议记录和截至某个时间的实际进展。长期跟进同一项工作，可以把材料放入ChatGPT项目，但每次生成周报仍要提供最新状态。
