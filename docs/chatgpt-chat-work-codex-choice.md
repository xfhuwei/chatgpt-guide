## 一、先用成果判断

| 你要完成的事 | 优先尝试 |
|---|---|
| 解释概念、修改一段话、讨论思路 | Chat |
| 综合资料做报告、表格、文档或演示 | Work |
| 在代码项目中修改功能、运行测试、查看技术细节 | Codex |

这是选用起点，并不是互不相通的能力清单。官方使用指南按上述工作方式介绍三者，同时强调材料、工具和成果检查。[官方使用指南](https://learn.chatgpt.com/docs/use-chatgpt)

<a id="section-02"></a>

## 二、同一任务可以分三个阶段

以虚构“培训准备”为例：先在Chat讨论40分钟如何安排；材料确定后，用Work制作讲义与演示；若需要一个报名人数计算小工具，再考虑Codex或具备相应工具的开发流程。

每次切换都说明当前有效材料，不假定另一个聊天中的全部内容已经自动带入。需要持续共享资料时，使用项目，并核对新对话是否在正确项目内。

## 三、三种请求怎样写才清楚

Chat请求可以是：

```text
我需要给8位新同事做40分钟培训。
先讨论三种安排方式，列出各自适合的条件。
日期和讲师尚未确定，暂不制作文件。
```

Work请求可进一步明确成果：

```text
采用我确认的安排和附上的练习材料。
制作一份可编辑讲义，包含时间表、练习和检查清单。
提供实际文件并检查数字、分页和待确认事项。
```

代码任务则应说明环境与验收：

```text
在这个练习项目中制作一个离线人数计算页面。
输入各组人数，显示合计；空白视为0，负数提示错误。
不要接入真实账号或支付；完成后用给定样例检查结果。
```

这些提示词是原创任务规格，不意味着当前账号已执行或都能访问相同工具。

## 四、模式、模型、工具和套餐分别检查

模式决定交互方式；模型与思考选项影响任务处理；工具决定能否读文件、访问网站或修改代码；套餐和组织设置约束实际可用能力。切换到更复杂模式，也不会自动获得一个未授权的云盘文件。

因此，输出不符合要求时先定位：是材料不足、工具不可用，还是任务本身需要进一步拆分。模型选择可看[模型与思考设置](chatgpt-models-thinking.md)，不必在每个模式教程里重建一张易过期的套餐表。

## 五、先完成一个小任务再扩大范围

不用为了入门同时学习所有开发界面。先选自己最常遇到的工作，准备小材料、明确输出、检查结果。做成后再增加文件数量、外部连接或自动化。

需要一条连续学习路线，可以从[七步入门与实践路线](chatgpt-new-user-learning-route.md)开始；要制作办公成果，直接看[Word与PPT文件](chatgpt-word-ppt-files.md)。
