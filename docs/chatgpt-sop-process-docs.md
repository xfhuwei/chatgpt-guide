# ChatGPT 编写 SOP：把零散经验整理成别人能够照做的操作流程

[知识库首页](../README.md) · [办公与内容创作](../catalog/topics/work.md) · [按问题找答案](../catalog/TASKS.md)

资料核对：2026-11-03。适用环境：文字或文档制作；以下文章配图流程为原创练习。

> **先看结论：** SOP是标准操作流程。写得好不好，要看第一次接手的人能否知道何时开始、每步做什么、出现异常找谁，以及怎样判断完成，而不是看格式是否像制度文件。

## 一、先把真实操作讲出来

使用这段虚构材料练习：

```text
作者交文章初稿时，正文中已有两处插图位置。
审阅者先改文字，再用演示账号截图。
图片包含账号信息时先遮盖，图片名与占位一致。
编辑把图插入正文，检查能否显示和是否对应步骤。
负责人确认后才发布；缺图或步骤不一致时退回补充。
```

这份材料已经给出角色和顺序。真实团队里如果没有负责人或发布权限，先列成待确认，不让模型凭空创造岗位制度。

<a id="section-02"></a>

## 二、让ChatGPT先列流程结构

```text
请把材料整理成文章配图SOP。
包含目的、适用范围、角色、开始条件、步骤、异常处理和完成标准。
每步写输入、动作、产出、检查点。
只使用已给规则，没有的时限和负责人写待确认。
```

这种要求把成果和检查边界写清，方法可参考[官方提示指南](https://learn.chatgpt.com/docs/prompting)。SOP内容仍应由实际执行者核对。

<a id="section-03"></a>

## 三、把模糊动作改成可检查动作

“处理图片”太宽泛，可以拆成“核对图片是否对应占位、检查隐私信息、确认文件名与格式”。“确认无误”则应明确检查正文步骤、图片内容和链接显示。

参考步骤表：

| 步骤 | 动作 | 完成标志 |
|---|---|---|
| 1 | 审阅文字和占位 | 两处截图需求清楚 |
| 2 | 按实际流程截图 | 图片对应真实界面 |
| 3 | 遮盖并命名 | 无需公开的信息已隐藏 |
| 4 | 插入正文 | 图片可显示，图注对应 |
| 5 | 负责人确认 | 有明确发布结论 |

<a id="section-04"></a>

## 四、一定补异常分支

```text
请补充三种异常处理：
没有对应功能入口；截图与正文按钮不同；图片含账号资料。
说明应停止在哪一步、补什么信息、交给谁确认。
不得用网上旧截图冒充本次实际操作。
```

遇到入口变化，应记录平台、版本和账号条件并修订教程；敏感信息未处理的图片不能直接进入公开稿。具体处理人未知时，继续标待确认。

## 五、让新人试走一遍再定稿

用一篇练习稿让未参与编写的人按SOP执行，记录他在哪一步需要追问。补充缺失动作，删掉无法执行的空泛要求。

版本记录写明何时改了什么，不只在标题加“最新版”。经常复用的流程可进一步整理成[技能](chatgpt-skills-reusable-workflows.md)，多人审阅则可用[Space协作](chatgpt-space-collaboration.md)。
